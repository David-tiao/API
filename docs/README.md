# 📚 API Extractor 文档中心

这里采用三条阅读路线，把理解项目、深入技术和实际操作分开。初学者不必先读懂源码或执行命令，技术读者也不必在入门概念中寻找公式。

## 1. 文件结构及功能

```text
docs/
├── README.md                       文档总导航与维护规则
├── 01-overview/                    零基础精简篇
│   └── README.md                   项目介绍、通俗术语、架构、文件职责、能力边界
├── 02-technical/                   专业技术篇

    └── README.md                   安装、启动、测试、结果检查与故障排查命令
```

## 2. 三条阅读路线

| 阅读目的 | 文档入口 |
|---|---|
| 完全零基础：理解项目及其作用，不执行命令 | [01 零基础精简篇](01-overview/README.md) |
| 专业学习：模块关系、程序运行流程与架构取舍 | [02.1 架构设计](02-technical/01-ARCHITECTURE.md) |
| 算法学习：公式、数学推导和实际实现之间的关系 | [02.2 算法与数学推导](02-technical/02-ALGORITHMS.md) |
| 技术答辩：了解各轮升级的内容和理由 | [02.3 版本简史](02-technical/03-VERSION_HISTORY.md) |
| 动手运行：环境、配置、启动、Docker、验收和排错 | [03 运行操作篇](03-operations/README.md) |

推荐先阅读零基础篇，然后按需进入专业篇或操作篇。所有现行运行命令统一维护在操作篇。

## 3. 文档维护原则

- 零基础篇：必要名词均用通俗语言解释，不放可执行命令。
- 专业篇：以实际源码为准，区分数学模型、启发式规则、真实测试和未验证假设；版本简史不虚构发布记录。
- 操作篇：命令与当前脚本保持一致，明确授权、环境、配置与网络前置条件。
- 代码改动后同步更新有关文档，避免重复维护同一套内容。
