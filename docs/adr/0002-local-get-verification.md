# ADR-0002：额外 GET 验证仅限本地、显式授权

- **状态**：采用；2026-11-22。
- **背景**：V12 不将只有静态证据的接口进入正式 result，减少虚假证据但可能损失 Recall。
- **决策**：增加 `ExplicitGetVerifier`，必须操作者自己在本地练习站点的配置中明确提供最多五条完整、已确认安全的 GET URL；它们必须存在于现有静态候选，并且落在 ScopeGuard 的允许范围内。仅在 2xx JSON 响应后制作与真实日志一致的 HAR，默认关闭，绝不盲目调用其他方法。
- **理由**：HEAD/OPTIONS 不能等价证明 GET 有效；凭空写请求日志违反伪造证据规则；自动发送 POST/DELETE 或未经批准的 GET 有状态改变风险。
- **弃用方案**：为隐藏站点定制 API 列表或把推测结果直接当请求证据。官方 3.6 不允许此类每站人工适配。
- **约束**：无 Query/凭据/fragment/占位符/跳转，不转发账号、Cookie 与自定义 Header；共用 RequestGate 与任务预算。GET 不是绝对只读，操作者需要额外确认。
- **代价**：正式评测默认没有这个字段，因此不增加官方召回；不处理认证、复杂参数、非 JSON；仅证明当前一次请求而非可重放性。
- **证据**：隔离 Python 3.13.5 的 87 项测试通过，含本轮 23 项离线测试；未运行真实 Docker 或评测网。
